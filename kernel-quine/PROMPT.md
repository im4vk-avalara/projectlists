# HARD CONSTRAINTS

1. The output must be byte-identical to the source file, including

2. No external file reading. The program cannot `open()` or `read()`

3. No "cheating" — the entire source is the program, no separate

4. The source must be hand-written, not generated by a quine 
   generator tool. (You may *understand* such tools, but the artifact 
   is hand-crafted.)
5. The program must terminate cleanly with exit code 0.

# WORKING PROTOCOL

For each task:

1. **Explain the structural strategy first.** Before any code, 
   describe: where is the "data" portion? Where is the "code" portion? 
   How does the code reconstruct the data?
2. **The classic pattern**: data section holds the source as a string; 
   code section prints the data twice — once as raw text (the data 
   part of the source), once with appropriate quoting (the code part 
   that re-emits it). Confirm we're using this pattern or a variant, 
   and explain.
3. **Handle the bootstrapping problem explicitly.** The data section 
   contains the code that prints the data section. How do we avoid 
   infinite recursion in the source representation? This is the 
   *interesting* problem.
4. **Test byte-equality after every change.** The verification command 
   `./quine | diff - quine.s` must return empty. Run it every iteration.
5. **Watch escape characters.** Newlines, tabs, quotes, backslashes — 
   each needs careful handling in both the data and the code paths.
6. **Use direct syscalls, no libc.** Calling `write` syscall directly 
   keeps the program self-contained and small.
